# Browser Credential Threat Model

Infinite Canvas is a local-first application. Browser storage may contain AI provider API keys, WebDAV credentials, Canvas Agent URL and connect token, model choices, and creation data. These values are intentionally not sent to a project-hosted backend, but any script executing in the same browser origin can read them. This is suitable for a personal or otherwise trusted browser environment, not a hostile shared-device or untrusted-plugin environment.

## Assets and boundaries

| Asset | Storage or path | Required boundary |
| --- | --- | --- |
| AI provider API keys and WebDAV credentials | Browser configuration storage | Only the configured provider and user-initiated browser requests receive them. Never place them in public issues, screenshots, diagnostics, or third-party scripts. |
| Canvas Agent URL and connect token | `localStorage` after an explicit connection | Treat as a local capability. Only use a trusted local or HTTPS endpoint; disconnect or clear browser site data when the device or profile is no longer trusted. |
| One-time `baseUrl` / `apiKey` URL parameters | Read at browser startup, then removed with `history.replaceState` | Do not share links before the parameters have been removed. Prefer entering long-lived credentials in Settings instead of links. |
| Canvas Agent session identity | `sessionStorage` | Scoped to one browser tab session and used only to bind Agent events and canvas tools to that tab. |
| Prompt sources, remote images, generated text, plugin metadata and Agent output | External input | Treat as untrusted display data, never as executable instructions or credentials. Image URLs are normalized and known unusable prompt thumbnails are rejected before loading. |

## Trust rules

- Third-party node plugins execute in the current page and can access browser-local data, including AI API keys. Install only code and update URLs you trust; a plugin is not a sandbox.
- Canvas Agent connects with an explicit URL and token. The client accepts only `http:` or `https:` endpoints, but protocol validation is not proof that the endpoint operator is trusted.
- FrameFlow browser reference images are copied as validated PNG bytes into Agent-managed reference storage before ImageGen reads them. A browser path or URL is not accepted as a managed reference by itself.
- Browser prompts, image URLs, machine-generated text, logs and error details are untrusted input. UI rendering must keep them as data; do not add HTML injection, script execution, or credential-bearing debug output.
- Agent logs redact credential-named fields, Data URLs, and common Bearer or assignment-style credentials. Redaction reduces accidental exposure but does not make it safe to paste real secrets into diagnostics.

## Known limits and next controls

The application still relies on same-origin browser storage, so an XSS issue or trusted-but-malicious plugin can expose local credentials. A Content Security Policy must be introduced incrementally because the current application uses inline theme startup code, locally installed plugins, direct provider requests, and user-configured endpoints. Before enforcing CSP, record the required script, style, image, connect and worker sources in a report-only-compatible configuration; do not silently block user-configured provider traffic.

When reporting a suspected issue, follow [Report a Vulnerability](security) and submit only redacted evidence.
