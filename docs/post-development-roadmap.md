# Infinite Canvas + FrameFlow 后期开发路线图

## 1. 审查结论

当前工作区已经具备较完整的 Infinite Canvas、FrameFlow 自动跑风格、机器审美评审、人工反馈、演化轨迹与运行血缘能力。现有单元测试、类型检查、生产构建和自动化浏览器首屏回归均通过，说明当前工作区可以继续开发。

当前最优先的问题已从“本机可运行”转为“可复现、可回退、关键流程可验收”：运行必需的工程基础设施已进入 fork 分支，并在隔离干净检出中完成安装、构建、测试与浏览器回归。原工作区的用户证据资产仍保持未跟踪且不纳入代码分支；当前验证范围和提交关联见 `docs/session-development-record.md`。后续不应把局部自动化或人工闭环外推为 95 项主清单全部验收。

本路线图不把 Docker 或容器部署纳入当前阶段。后期如重新提出容器部署需求，再单独恢复该验收线。

## 3. 风险与优先级

| 优先级 | 风险 | 影响 | 处理原则 |
| --- | --- | --- | --- |
| P0 | 当前工作区无法由 `HEAD` 独立重建 | 换机、回退或协作时可能缺失关键依赖和测试基础设施 | 先分类、再形成可恢复检查点，禁止清理用户文件 |
| P0 | 95 项待测试内容没有状态矩阵 | 已实现、已自动化、需手测和失效项目混在一起 | 给每项增加状态、证据和负责人，不以文档存在代替验收 |
| P0 | FrameFlow 主闭环缺少一条可重复的端到端验收 | 自动跑、停止/继续、机器学习与归档容易发生跨页面回归 | 使用一次性测试数据建立完整闭环，不碰真实资产 |
| P1 | 多个核心模块体积过大 | 修改耦合、回归范围和评审成本持续上升 | 先补特征测试，再按职责拆分，不与新功能混做 |
| P1 | 中英文 TODO 曾发生内容漂移 | 两个入口展示不同的后续计划 | 使用同一任务源或增加自动一致性检查 |
| P1 | 浏览器本地保存连接信息和 AI 密钥 | XSS 或第三方内容风险会扩大凭据暴露面 | 明确信任边界，补 CSP、日志脱敏与外部内容约束 |
| P1 | 格式检查仍豁免约 205 个历史文件 | 格式门禁不能覆盖全仓 | 按触达模块逐步缩小基线，禁止一次性全仓重排 |
| P2 | Agent、Skill、自动推荐与跨设备协作待扩展 | 新能力会增加数据模型、授权和迁移复杂度 | 稳定主闭环后分阶段进入，保持显式授权 |

## 4. 分阶段开发计划

### 阶段 A：建立可恢复、可复现的工程基线（P0，已完成）

目标：任何后续开发开始前，先保证当前成果不会因工作树损坏或缺失未跟踪文件而丢失。

任务：

1. 对所有修改和未跟踪文件分类：业务源码、构建依赖、测试、证据、缓存、真实资产、临时产物。
2. 检查敏感信息和真实数据后，把运行必需的源码与工程文件纳入一个可恢复检查点；不提交缓存、测试截图和真实资产。
3. 重点核对当前 `HEAD` 中缺失但工作区正在使用的路径：
   - `web/design-system/`
   - `web/e2e/`
   - `web/playwright.config.ts`
   - `web/scripts/`
   - `docs/scripts/`
   - `.github/workflows/quality.yml`
4. 在新的干净工作树或全新检出副本中安装依赖并执行构建、测试和浏览器回归。
5. 明确 Web 与文档站各自的规范包管理器和锁文件；CI 与本地命令保持一致。

退出条件：

- 可从版本库独立安装和启动，不依赖原工作区残留文件。
- 三个子项目的测试、类型检查和生产构建通过。
- 自动化浏览器回归通过。
- 原工作树与真实资产未被清理、覆盖或迁移。

完成记录：用户未跟踪项已只读分类，运行必需文件已进入 fork 分支；隔离浅克隆已在 `600ba8e` 完成 Web 49 项 Vitest、15 项 Playwright、Canvas Agent 184 项测试及三处生产构建。详细命令、提交和边界见会话记录第 18 至 25 节。

### 阶段 B：关闭 FrameFlow 验收债务（P0，主闭环已覆盖）

目标：把“功能存在”变成“每个关键状态可重复验证”。

任务：

1. 为 95 项中文待测试清单建立状态矩阵：`未验证`、`自动化通过`、`人工通过`、`已失效`、`阻塞`。
2. 每项记录验证入口、测试数据、预期结果和证据；英文页面只保留同步摘要。
3. 建立一次性 FrameFlow 端到端夹具，至少覆盖：
   - 创建独立需求并输入自由方向。
   - 启动限定轮数的自动跑。
   - Codex 自动评分、评论、强化/规避学习。
   - 暂停、继续和停止，不产生孤儿运行状态。
   - 人工评分、Comment、“不喜欢并学习”和“删除但不学习”。
   - 轨迹、待审、需求内偏好和运行血缘保持同一任务上下文。
   - 删除或归档需求后，相关入口不再显示为活动任务，历史证据按规则只读保留。
4. 测试数据必须与真实资产隔离，测试结束后只清理测试夹具自身。
5. 对自动跑状态机增加失败恢复用例：页面刷新、生成中断、机器评审失败、停止后迟到结果隔离。

退出条件：

- P0 流程拥有自动化证据与一次内置浏览器人工验收记录。
- 页面中的任务、轮次、批次、需求和运行标识一致且可追溯。
- 暂停、继续、停止、归档与删除语义在 UI、存储和 Agent 中一致。

完成边界：状态矩阵、一次性 HTTP/Core 夹具、隔离浏览器回归及内置浏览器主闭环均已完成。矩阵中仍有 49 项未验证；这些项属于逐页、响应式、真实外部服务或扩展场景的持续验收债务，不能因 P0 主闭环通过而自动关闭。

### 阶段 C：降低核心模块耦合（P1，进行中）

目标：在不改变现有行为的前提下，让后续功能开发具备可控的修改边界。

优先拆分对象：

| 文件 | 当前职责问题 | 建议边界 |
| --- | --- | --- |
| `web/src/pages/canvas/project.tsx` | 画布交互、生成调度、持久化和页面展示集中在同一文件 | 生成编排、项目持久化、交互控制器、纯展示组件 |
| `web/src/components/agent/local-agent-panel.tsx` | 连接、会话、流式输出、历史和 UI 状态混合 | 连接层、会话状态、消息流、展示面板 |
| `canvas-agent/src/frameflow/core.ts` | 命令编排、领域规则、存储投影和错误恢复耦合 | 命令处理器、纯领域服务、投影/查询、恢复策略 |
| `canvas-agent/src/agent/codex.ts` 与 `codex-client.ts` | Provider 协议、调用细节和业务语义边界较宽 | Provider 接口、传输客户端、结果规范化、业务适配器 |

执行约束：

- 先补现状特征测试，再移动代码。
- 每次只拆一个职责，保持 UI、存储格式与 API 兼容。
- 重构与新功能分开提交和验收。
- 不进行全仓格式化；仅格式化本次触达文件，并逐步缩小格式豁免基线。

退出条件：

- 核心编排具备清晰输入、输出和错误边界。
- 关键状态转换可以脱离 UI 做单元测试。
- 现有 Web 50 项、Canvas Agent 191 项测试、构建和 18 项浏览器回归保持通过；Web 格式基线检查当前仍报告两个未触达的既有文件，须在独立格式治理切片中处理。

当前进展：已分离 Codex 的 FrameFlow/图像请求构建、FrameFlow 的重启恢复、事件历史查询、事务结果映射、Prompt 血缘、自动跑轨迹与 Requirement 查询投影；`FrameFlowCore` 仍包含命令编排、投影写入与领域规则，需继续按单一职责小步拆分。

### 阶段 D：安全、可观测性与文档治理（P1，进行中）

目标：让浏览器直连、外部内容导入和自动运行具备清晰、可审计的边界。

任务：

1. 为浏览器本地保存的 Agent URL、Token、模型设置和 AI API Key 建立明确的威胁模型。
2. 评估并实施适配当前内联主题脚本、插件与资源加载方式的 CSP；先报告模式，再逐步收紧。
3. 对日志、错误上报、导出与诊断信息增加凭据脱敏测试。
4. 把外部 Prompt 仓库、图片 URL 和机器生成文本统一视为不可信输入，保留现有 URL 归一化，并补充协议、来源和失败降级测试。
5. 为自动跑增加结构化运行事件：任务、轮次、批次、状态转换、停止原因、评审版本和迟到结果处理。
6. 保持 ADR 作为架构决策唯一入口；本路线图不新增重复 ADR 系统。
7. 为 TODO 中英文内容增加自动一致性检查，防止两份清单再次漂移。

退出条件：

- 敏感信息不会出现在普通日志、前端错误提示或测试产物中。
- 自动跑失败可从运行事件定位到具体阶段。
- 中英文 TODO 和关键验收状态有自动一致性门禁。

当前进展：威胁模型、日志凭据脱敏测试、Prompt URL 协议/来源约束、停止原因事件和双语 TODO 一致性检查已经落地；Vercel 的 CSP 目前仅为报告模式，仍需基于部署观测决定是否与如何收紧为强制策略。

### 阶段 E：功能扩展（P2）

在阶段 A 至 D 达到退出条件后，再按独立需求进入：

1. 把 Claude Code CLI Adapter 升级为 Claude Agent SDK Adapter，并完善工具队列体验。
2. 补充 Agent Skill 的网络检索安装、资源文件管理和可控本地记忆。
3. 在用户明确授权后，增加 Prompt 自动拆解、跨批次命中率分析和推荐策略；机器建议不得静默覆盖人工 Prompt。
4. 设计跨设备或团队协作前，先定义数据所有权、冲突合并、迁移、备份与撤销模型。

## 5. 建议迭代顺序

1. 基线分类与可恢复检查点。
2. 干净检出复现。
3. 95 项待测试状态矩阵。
4. FrameFlow 完整闭环夹具与内置浏览器验收。
5. 核心模块分层重构。
6. 安全与运行可观测性。
7. Agent、Skill、Prompt 智能化和跨设备扩展。

任何阶段出现跨需求数据污染、无法停止的自动运行、迟到结果写回活动任务、凭据泄露或无法从版本库重建时，应暂停功能扩展并回到相应的 P0/P1 门禁。
